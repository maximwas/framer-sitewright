How it works

Your agent talks to Sitewright. Sitewright works in your open Framer project.

Sitewright is a local MCP server. It reaches Framer through a small companion plugin in the editor, so changes appear on the canvas as they happen, and through Framer's Server API when you add a key for the parts only Framer's agent layer can do.

Your agent

Claude Code, Cursor or Codex

You describe the site. The agent plans the work and calls Sitewright's tools.

On your computer

Sitewright

58 tools, design rules and a layout audit. Records every change in a journal you can undo.

In the editor

Your Framer project

The plugin applies each change live. A Server API key, if you add one, unlocks the rest.

  1. Run the setup

    npx -y sitewright@latest connects your agent, asks what it may do, and offers to save a Server API key per project.

  2. Open the plugin

    In Framer, open the Sitewright plugin and click Connect. The journal window it opens carries the connection: keep it open.

  3. Ask your agent

    “Build a landing page for a ceramics studio, with a blog in the CMS and a Dutch version.” Watch it land on the canvas.

Features

Built from real client sites, not from a demo.

Every rule in Sitewright came from building real Framer sites through it: what Framer silently rewrites, what breaks on phones, and what makes a page look generated.

A journal with undo

Every call is recorded with what changed and how it reached Framer. Undo the last change, a change and everything after it, or go back to a checkpoint.

Keys stay with you

Server API keys are saved per project on your computer and never leave it. No account, no telemetry, no cloud in the middle.

Works without a key

With just the plugin, the agent builds pages from frames and text, styles, breakpoints, gradients, images, CMS content and translations.

A layout audit after every change

Catches what looks broken once published: misaligned edges, uneven cards, default-blue links, fixed sizes that break on phones, missing headings.

A design guide built in

The order of work, layout and type rules, direction measured on top Framer sites, and a checklist before a page is handed over.

Desktop to phone

Adds Tablet and Phone breakpoints and adapts their copies, so a page holds at 1440, 810 and 390 pixels wide.

Two ways to reach Framer

Start with the plugin. Add a key when you need the rest.

Calls go to the plugin first, so they land live in the editor. Work only Framer's agent layer can do goes through the Server API of the same project.

Path What you need What works
Plugin The Sitewright plugin open in the Framer editor, connected. Color tokens and text styles, fonts, pages from frames and text (layout, size, fills, linear gradients, images, borders, links), breakpoints, SVG, component controls, CMS, translations, code files, the editor selection.
Server API Your own key from Framer → Site Settings → General → API Keys, saved per project. Everything above, plus effects and transitions, variants and components, rich text, shadows, screenshots, Framer's DSL reference, and the icon, component and stock photo catalogs.

Nothing runs while the plugin is not connected, so a change never lands in a project you did not open.

Privacy

Your projects and keys never leave your machine.

Sitewright runs on your computer and talks only to Framer. There is no Sitewright server, so there is nothing to sign up for and nothing that sees your work.

  • Keys in a local file. One Server API key per project in ~/.sitewright, readable only by you.
  • No telemetry, no account. Sitewright does not collect or send usage data.
  • The right project, always. Changes go to the project the plugin is open in, or to the one you name.
  • You decide what it may do. Custom code and code components stay off until you switch them on. Publishing happens only when you ask.

FAQ

Questions

Is Sitewright made by Framer?

No. Sitewright is an independent, unofficial tool. It is not affiliated with or endorsed by Framer. “Framer” is a trademark of Framer B.V.

What does it cost?

Nothing. Sitewright is free and open source under the MIT license, with no paid tier. Some Framer features, such as localization or CMS limits, depend on your Framer plan.

Which agents does it work with?

Any agent that speaks MCP. The setup connects Claude Code, Cursor and Codex for you; for others, npx sitewright setup --print prints the config.

Do I need a Server API key?

No. With the plugin alone the agent builds and edits pages, styles, breakpoints, CMS and translations. A key adds effects, components and variants, rich text, screenshots and Framer's catalogs.

Can the agent break my site?

It works in the editor, not on your live site: nothing is published unless you ask. Every change is in the journal, and most can be undone with one click. The journal says when a change cannot be undone, such as CMS edits for now, and returns what it removed.

How is it different from Framer's own agent?

Sitewright runs as a fast local server with the journal and undo, a layout audit after every change, design rules from real builds, and the plugin path that works without a key. You can use it next to Framer's tools.
